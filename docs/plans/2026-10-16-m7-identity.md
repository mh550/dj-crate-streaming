# M7: identity (songs, versions, copies) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task, with superpowers:test-driven-development.
> Steps use checkbox (`- [ ]`) syntax for tracking. **No library file is written before Task 13**, and Task 13
> is gated on Michael's review of the proposal.

**Goal:** one `identity` module decides what counts as the same song, version and copy. Matching, scoring,
dedupe and verify all use it. Version preferences live in an editable policy file. A reviewed backfill fills in
the recording and work ids of the existing library, so Navidrome's song ids stop depending on tags and paths.

**Why M7 exists** (read this before judging an edge case):
1. **One owner per fact.** Which version a file *is* lives in its tags: `MUSICBRAINZ_TRACKID`, the version
   field (Vorbis `VERSION` / ID3 `TIT3`) and the title. Which versions make up one song is *derived* by
   `sourcing/identity.py` and never stored.
2. **Five normalisers disagree today:** `scorer.norm`/`_NOISE`, `import_playlist.norm`/`_core`,
   `store._loose`, `dedupe._norm` and `tag_rules._same`. For example, the scorer discards "original mix" as
   noise, but under D16 it is a version label. Folding them into `identity` makes matching, scoring, dedupe and
   verify agree.
3. **The invariants.** A version has at most one copy, and a better copy replaces the old one. Several versions of
   a song may coexist, and a new version is never a replacement. M8's copy replacement needs the same-version
   test that M7 builds.
4. **Only 98 of 831 files carry a recording id.** Navidrome uses it to recognise a song after a retag plus a
   move (the M2 playlist breakage). The backfill is a *proposal* first: a report Michael reviews, then a narrow
   writer (`write_minimal`, id fields only). beets never writes existing files (M2 damage).
5. **Version preferences are Michael's policy** (D16, "not set in stone"). So they go in an editable file
   together with the tiers, not in code. The tiers move there with identical values (D17 is open).

**Architecture:**
- `sourcing/identity.py` is pure and stdlib-only. It provides:
  - folding: `words`, `loose`;
  - `lead_artist`;
  - `parse_title`: base title, version label kinds, credit, copy markers;
  - `song_key`;
  - `same_version` over a small `Copy` record.
- The five normalisers become calls into it.
- `deploy/policy.toml` holds the tiers and the `versions:` preferences, read by `sourcing/policy.py` with `tomllib`.
- The import matcher (`choose`) asks three questions in order: same recording, then same version, then an
  accepted other version.
- The scorer gains a version preference term. Crate rows are copy upgrades and refuse other versions.
- `fetch` tells `verify` whether the download is a copy upgrade or a new version.
- `sourcing/musicbrainz.py` gains a rate-limited client.
- `scripts/identity_backfill.py` writes a proposal and a report (`propose`), applies only the accepted id fields
  (`apply`), and can undo that (`revert`). It runs in the worker container. beets is not used in M7.

**Tech Stack:** stdlib Python 3.12 (`tomllib`, `sqlite3`, `urllib`), mediafile/mutagen, fpcalc (only with
`ACOUSTID_KEY`), MusicBrainz web service, Docker Compose.

**Spec:** `docs/specs/2026-10-16-ownership-and-identity.md`: all of Part 2, Part 1 "Where beets fits" (the M7
bullet) and fact #8. The runbook queue is `~/projects/OVERNIGHT-2.md` § M7, with "Decisions already made" D16, D17
and D22. Beets traps: `~/projects/HANDOFF-M6.md` "Hard-won facts" and the M6 ledger
`.superpowers/sdd/2026-10-16-m6-worker-and-filing/progress.md` ("Debug (filer flake)").

### Task 1: `sourcing/identity.py` (model: **Opus**: the parsing rules are the core of the milestone)

**Files:**
- Create: `sourcing/identity.py`
- Test: `tests/test_identity.py`

**Interfaces:**
- Produces:
  ```python
  KINDS = ("edit", "extended", "club", "dub", "instrumental", "acappella", "live", "remix", "reedit", "demo", "alt", "original")
  NEUTRAL = frozenset({"original"})          # counts for preferences, not for the version key

  def words(s: str | None, *, noise: bool = False) -> str
      # NFKD + drop combining marks, casefold, "&" -> " and ", every non-alphanumeric run -> one space, strip.
      # noise=True also drops the copy/credit words: feat, ft, featuring, remaster, remastered, "<4 digits> remaster",
      # "album version", explicit, clean, hq, hd. ("original mix" is NOT noise any more: D16.)
  def loose(s: str | None) -> str            # words(s) with the spaces removed
  def lead_artist(artist: str | None) -> str  # first part before " • ", ";", " feat.", " ft.", " featuring " (case-insensitive); stripped
  @dataclass(frozen=True)
  class Title:
      base: str                # the title without decorations, as written (stripped)
      label: str               # the label decorations as written, joined with ", " in reading order; "" when none
      kinds: frozenset[str]    # subset of KINDS
      by: str                  # loose credit ("tommoulton"); "" when none
      copy_note: str           # copy-marker decorations as written ("Remastered 2011", "feat. X"), ", "-joined
      @property
      def key(self) -> tuple[tuple[str, ...], str]   # (sorted(kinds - NEUTRAL), by)
  def parse_title(title: str | None, artist: str | None = None, version_tag: str | None = None) -> Title
  def song_key(artist: str | None, title: str | None) -> str   # f"{loose(lead_artist(artist))}|{loose(parse_title(title, artist).base)}"
  @dataclass(frozen=True)
  class Copy:
      artist: str; title: str; length_s: float | None
      recording_id: str = ""; work_id: str = ""; version_tag: str = ""
  def same_version(a: Copy, b: Copy, tol_s: float = 4.0) -> bool
  def version_groups(copies: list[Copy], tol_s: float = 4.0) -> list[list[int]]   # indices; only groups of ≥ 2
  ```
- `parse_title`, in this order:
  1. Junk: strip a trailing run of `(\.(mp3|flac|m4a|wav))+` and a leading `^\d{1,3}\s*-\s*`. Do this up to 3
     times, because they stack (today's `import_playlist._NOISE` cases).
  2. With `artist`, strip that lead artist when it is glued on as `"<lead> - "` or `" - <lead>"`. The comparison
     is by `loose`.
  3. Peel trailing decorations from the right. A decoration is a balanced trailing `(…)`/`[…]` group, or the text
     after the last `" - "`. A decoration wrapped in brackets after `" - "` (`" - (Daft Punk Remix)"`) is one
     decoration. Then classify it:
     - **Copy marker:** the remaster family (the `tag_rules._REMASTER` words, including "Remastered 2001/Rudy
       Van Gelder Edition"), `feat.`/`ft.`/`featuring`/`with X`, `album version`, `explicit`, `clean` or `bonus
       track`. It goes to `copy_note`, and peeling goes on.
     - **Label:** the decoration contains a vocabulary token (table below). Its kinds and credit are added, and
       peeling goes on.
     - **Anything else:** stop, and the decoration stays in `base`.
     - A leading group ("(They Long to Be) Close to You") is never a decoration.
  4. `version_tag`: parse it as one decoration. Use it only when it yields kinds. Otherwise ignore it (fact 2).
- The vocabulary. Match on the raw decoration for the 12"/7" patterns, and on `words()` for the rest, at word
  boundaries:

  | Kind | Tokens |
  |---|---|
  | extended | `12\s*("|”|″|''|'|in\b|inch)`, `extended`, `long version` (when any 12"/7" token is present, "single" adds nothing) |
  | edit | `7\s*("|”|''|in\b|inch)`, `edit`, `radio`, `single version`, `single edit`, `short version` |
  | reedit | `re-edit`, `reedit`, `re edit`; also `edit` with a non-empty credit and no other kind |
  | club / dub / live / demo | `club` / `dub` / `live` / `demo` |
  | instrumental | `instrumental`, `inst` |
  | acappella | `a cappella`, `acappella`, `acapella`, `a capella` |
  | remix | `remix`, `rmx`, `rework`; also `mix` when nothing else in the decoration is a kind (a named mix, or a bare "Mix") |
  | alt | `alternate`, `alt take`, `take \d+`, `medley`, `version` with a qualifier that is no other token ("Disco Version", "Sax Version") |
  | original | `original`, `original mix`, `original version` |

  The credit `by` is the `loose()` of the decoration's words, after removing the matched tokens, the filler words
  `mix`, `version`, `single` and `by`, and 4-digit years. When `edit` becomes `reedit` (an edit with a credit), it
  replaces `edit` in `kinds`.
- `same_version(a, b)`:
  - When both carry a recording id, they are the same version exactly when the ids are equal (case-insensitive).
  - Otherwise all of the following must hold:
    1. the same lead artist (`loose`);
    2. the same song: equal work ids when both have one, else equal `loose(base)`. Two different work ids → False;

**Interfaces:**
- Consumes: `parse_title`, `loose`, `lead_artist` (Task 1), and `TIERS[...].accept_versions` (Task 3).
- Produces:
  - `choose(row: Row, hits: list[Song], accept: frozenset[str] = frozenset()) -> Match`.
  - `Match.how: str | None` = `"same recording"` | `"same version"` | `"other version: <hit label>"` for matches.
  - `why` gains the value `"other version"` (a hit of the same song with a different label that the tier does not
    accept).
- The order. The row is parsed with `want = parse_title(row.title, lead)` and each hit with
  `parse_title(h.title, lead)`. "Title fits" is today's `_title_fits`, applied to the **base** titles.

     (case-insensitive) → `_decide(..., how="same recording")`.

     - With a row length: today's `_by_length` restricted to hits with `key == want.key` → `_decide(..., how="same version")`.
     - Without a length: the named hits with an equal `loose(base)` and an equal `key`.

     `key != want.key` and `kinds & accept`. One version after the copy collapse → `matched`,
     `how=f"other version: {label}"`. Several → `ambiguous`, `why="several versions"`.
  4. **Otherwise, today's fallbacks:**
     - With a length: a same song exists but no step matched → `ambiguous`, `why="other version"` when some hit
       has another key and the right length (±4 s), else `"length differs"`.
     - Without a length: hits that only contain the title → `"title differs"`.
     - Else `missing`.
- `_decide` treats hits as one track when their `(loose(base), key)` agree and their lengths are within ±4 s. That
  replaces today's `{_core(...)}` set.
- `import_playlist(...)` passes `accept=frozenset(TIERS[tier or IMPORT_TIER].accept_versions)`. For every match
  whose `how` starts with `"other version"`, it appends to `notes`:
  `f"matched with another version: {m.row.position} {m.row.artist} — {m.row.title} → {m.title}"`. `choose` stores

       exactly one work.

     `loose(release) == loose(album)` for any release; one left → `isrc`. Otherwise go on to step 3.

     album. One left → `search`, else `ambiguous` with the candidate ids. None → `none`.

       `write["acoustid_id"] = that entry's "acoustid"`.
     - If AcoustID's top id disagrees with a `search` pick → `conflict`.
     - A lookup error → the why notes it, and the class is unchanged.
  5. **Work id for the `search`/`acoustid` classes:** call `mb.recording(pick)` and add `mb_workid` when there
     is exactly one work and the file has none. The `isrc` class takes its work from the isrc response.
  6. For `isrc`/`search`/`acoustid`, `write["mb_trackid"] = pick`.

### Task 9: `apply` and `revert` (model: **Opus**: this is the one code path that writes library tags)

**Files:**

**Interfaces:**

- Produces:
  ```python
  @dataclass
  class ApplyReport:
      written: list[str]; skipped: list[tuple[str, str]]; problems: list[str]

            writer=None, navidrome=None, navidrome_db: Path | None = None,
            scan_timeout_s: float = 600, poll_s: float = 2) -> ApplyReport
  def revert(log: Path, music_root: Path, *, writer=None) -> int
  ```
- `apply`, in order:
  1. Select the rows with a non-empty `write`, `not row.get("skip")`, and either `row["cls"] in classes` (when
     `classes` is given) or `row["accept"]` (when it is not).
  2. Per row:
     - A file whose `size`/`mtime_ns` differ from the proposal → skipped `"changed since the proposal"`.
     - Re-read the tags with mediafile. Any field in `write` that is now non-empty → skipped
       `"already has <field>"`. **It is never overwritten**, even with the same value.

  4. `before = {path: id}` for the selected paths, from `navidrome_db` (`open_ro`, `SELECT id, path FROM media_file
     WHERE NOT missing`), when the db is given.

     per file.
  6. With `navidrome`: `start_scan()`, then poll `scan_status()["scanning"]` until it is false or the timeout passes.
     A timeout is a problem.
  7. With `navidrome_db`, after the scan:
     - Every selected path must still have the same id. Otherwise: problem `"id changed: <path> <old> → <new>"`.
     - When the table has `mbz_recording_id`, it must equal the written `mb_trackid`. Otherwise: problem
       `"Navidrome does not show the recording id for <path>"`.
     - Then `export_playlists.check(navidrome_db, music_root, music_root / "_playlists")`, whose lines are
       appended to the problems.
- `revert` goes through the log's lines from last to first. It writes `{field: ""}` for each written field, but only
  when the file's current value still equals what was written. It returns the number of files reverted.
