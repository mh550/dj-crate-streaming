# M3: dedupe the redundant copies — Implementation Plan

> REQUIRED SUB-SKILL: superpowers:executing-plans (inline) with superpowers:test-driven-development.

**Goal:** the 28 redundant copies in `/srv/music` (27 groups in `docs/library-map.csv` `other_copies`) go
to trash, every playlist entry pointing at one is repointed in place to the kept copy, Navidrome ends at
**831 songs**, and every move is logged with its reverse command (spec §4.2, D3).

**Facts (2026-10-15):** all 55 files of the 27 groups exist after M2's moves; 31 of them are in ≥1
playlist; 1 crate is enabled ("sockseek / clouds", 2 tracks). The stream hash in library-map
(`ffmpeg -c copy`) is not tag-independent for mp3s with ID3v1 (M2 repair), so identity is re-checked
with a **decoded** audio md5. Example: "Butcher Brown/…/I Can Say To You" and "Jamiroquai/…/I Can Say To
You" decode to the same md5, same title and album: one copy is in a wrong folder. `/srv/_trash` needs
root (Needs Michael), so trash is `/srv/docker/_trash/<date>/` (same disk, in the nightly backup).

**Design — `scripts/dedupe_copies.py plan | repoint | trash`:**
- `plan` (host; navidrome.db read-only): per group, decode-md5 every file; a group is **auto** only if all
  decode to the same md5 *and* their titles normalise equal; keep = `library_map._copy_rank` minimum
  (no `.1`, not Compilations/Singles/_ , then alphabetical); else the group is listed for a person.
  Playlists: `remap(entries, copy→kept)` replaces a copy in place, or drops it when the kept song is
  already in that playlist. Writes `/srv/docker/crates/dedupe-plan.json` (= `/data/…` in the crates
  container) and `docs/dedupe-report.md`.
- `repoint` (crates container: needs Navidrome credentials): per changed playlist, refuse if it changed
  since the plan; else one `updatePlaylist` that removes from the first changed index to the end and
  re-adds the new tail (Navidrome applies remove-then-add atomically; same technique as fetch.py).
  Idempotent: a playlist already equal to the plan's `after` is skipped.
- `trash` (host): refuses while navidrome.db still has a playlist entry for any copy; moves each copy to
  `<trash>/<relative path>`, appends `mv '<trash>' '<original>'` to `<trash>/MOVES.txt`, removes the
  beets item (`remove(delete=False)`), and updates library-map (`other_copies` drops it; a `new_path`
  that was the copy points at the kept file).
- Then: Navidrome full scan → 831 songs, 0 playlist entries on missing files; `crates.cli reconcile`;
  `export_playlists export && check`.

**Review focus:** a copy present twice in one playlist; the kept song already in the playlist; a
playlist Michael edited between plan and repoint; a group whose titles differ (same audio, mislabelled
file); re-running every command; a crash mid-`trash` (each move logged before the next).
